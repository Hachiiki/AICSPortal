## Content Moderation

New epic (added 2026-10-16, owner-requested). Scope covers every user-authored string that reaches the database: announcements (admin), section notifications (faculty), task submissions, profile fields, and links in uploaded materials. Primary languages: English and Filipino. The engine runs server-side in the API layer; any client-side copy is for instant feedback only and is never the enforcement point.

### Remaining
- [x] **Moderation engine with five independent rule sets (DONE 2026-10-16)**. `src/lib/moderation/` shipped with category matchers for profanity / harassment / sexual (obscenity engine + our curated bilingual datasets), URL trusted-domain policy, and the allowlist false-positive guard, plus per-surface policy tables (sexual + harassment reject; profanity + untrusted links flag) and the moderation_logs audit writer. A second "glue" matcher per category catches separator-hidden masking ("f u c k", "g a g o") with junction-safe pattern filtering, see docs/moderation-library-vetting.md §9 for the false-positive class this prevented ("data analysis", "ang gatas"). Contextual entries (English clinical anatomy; Filipino folk-tale/music/literary registers) flag for review instead of rejecting, reviewer verdict 2026-10-16, PR #45.
  1. **Profanity and abusive language**: English and Filipino vocabulary.
  2. **Harassment and discriminatory language**: slurs, threats, targeting of protected groups; kept distinct from generic profanity so the action can differ.
  3. **Sexual-content classification**: its own category, not lumped into profanity.
  4. **Website and URL restrictions**: detect external links and apply policy per audience (block vs flag for review), with a trusted-domain allowlist (school site, Cloudinary, LMS).
  5. **Allowlisted words (false-positive guard)**: exact-match and word-boundary-safe exemptions evaluated before anything is flagged (English/Filipino substrings inside legitimate words, academic and medical terms).
- [x] **Library vetting gate (DONE 2026-10-16)**: decision record at docs/moderation-library-vetting.md (all four gate points verified against live sources on 2026-10-16). Engine chosen: obscenity (MIT, 359K downloads/week, active Aug 2026, TypeScript, zero deps; custom datasets carry our Filipino list; whitelist + word boundaries are first-class). Filipino data: jromest filipino-badwords-list (MIT, 97 entries) plus LDNOOBW fil (CC-BY-4.0, 14 entries, attribution required), both requiring our curation, concrete false-positive traps found (boto = vote, brocha = paintbrush, gaga, kiki, habal, inutil, hudas). Hosted APIs rejected on the language gate: Perspective has no Filipino (language table verified via rendered docs), Azure Content Moderator deprecated (retires 2027-03-15), Azure Content Safety untrained for Filipino, OpenAI moderation unverified for Filipino (kept as a possible optional flag-only layer). Runner-up engine noted: AllProfanity. No hosted dependency; exactly one MIT runtime dependency.
